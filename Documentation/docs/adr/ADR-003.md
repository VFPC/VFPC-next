# ADR-003 — Controller Scope from UKCP Position Coverage

- **Decision status:** Accepted
- **Acceptance recorded:** 2 November 2026, in the controller-scope review chat
- **Supersedes:** [ADR-001](ADR-001.md) and [ADR-002](ADR-002.md)
- **Implementation status:** Implemented in the working source; Debug and Release Win32 builds passed on 2 November 2026 (zero warnings/errors); normal-scope and simulated lookup failure/recovery Sweatbox checks passed on 2–3 November 2026; verification limits, commit and release remain outstanding

## Context and provenance

The project owner identified shared APP coverage, observer review requirements,
and the need to exclude area-controller selections outside configured coverage.
The owner supplied a response attributed to UKCP's
`GET https://ukcp.vatsim.uk/api/controller-positions-v2`. The attached array
contained 342 positions, unique callsigns, and `top_down` airport arrays; 60
records had empty arrays. No `_OBS` records were present. This is supplied
response evidence, not a guarantee of production availability or API stability.

Examples in that response:

| Callsign | `top_down` |
|---|---|
| EGPH_DEL / EGPH_GND / EGPH_TWR / EGPH_APP | EGPH |
| ESSEX_APP | EGSS, EGGW, EGSC |
| SCO_CTR | 14 airports including EGPH and EGPF |
| SCO_SOL_CTR | EGPH, EGPF, EGPK |
| EGPH_F_APP | Empty |

The owner explicitly agreed to UKCP filtering, the OBS exception and fail-closed
operational scope, then authorised source changes with explanatory comments.
This supersedes the earlier decision that UKCP must be advisory only. Historical
records remain available; their implementation observations describe earlier
source and are not current verification evidence.

## Decision

| Position | Effective validation airport set |
|---|---|
| Recognised airport-specific DEL/GND/TWR | Exact UKCP record's single airport, matching the callsign prefix; independent of Runway Activity |
| Recognised APP/CTR | Departure-active Runway Activity airports intersected with the exact record's `top_down` |
| Callsign ending `_OBS` | Departure-active Runway Activity airports; UKCP lookup not required |
| Unknown operational callsign, unsupported suffix or empty mapping | Empty set, with an explanation |

Use the full callsign after trimming and uppercasing. Do not remove sector
identifiers or guess aliases. A mapping with one airport does not make a CTR
position an airport-specific position. For local DEL/GND/TWR, require a four-letter
airport prefix that agrees with the one mapped airport; inconsistent/multi-airport
local mappings pause validation instead of choosing an airport arbitrarily.

Mode follows the callsign suffix. Facility and `IsController()` are diagnostic:
`SCO_CTR` with APP facility still uses area selection. Rating must not determine
scope. The SDK documents facility values 1 through 6 for FSS/DEL/GND/TWR/APP/CTR,
but no OBS facility value. Its observer rating value is a different concept.
`IsController()==false` alone must not classify a session as OBS.

Runway Activity is read directly from sector-file airport departure-active flags,
not inferred from Departure List membership. Arrival flags do not enable
departure validation. A local airport missing from departure Runway Activity
produces a warning while retaining eligibility. A failed scan must not publish
a partial airport list: APP/CTR/OBS pause, while resolvable fixed local scope is
retained with a warning.

Preserve flight-origin snapshot lookup and the existing per-flight assigned
departure-runway gate. Selecting an airport or loading its data does not satisfy
that gate. No new runway-validity or active-runway matching rule is introduced.

## Cache, threading and recovery

- Fetch the public UKCP endpoint on a dedicated cancellable worker. Reuse the
  existing HTTP transport settings; do not route this lookup through the SID API
  failure messages or change the constraint source.
- Validate a complete nonempty position array, unique normalised callsigns and
  airport ICAO arrays before replacing the lookup. Empty `top_down` arrays are
  valid and distinct from missing data. Reject the whole replacement on a bad
  record; retain existing valid data after refresh failure.
- Keep the cache in memory for the connected session. Refresh on connection and
  explicit `.vfpc scope reload`; no periodic retry or persistent disk cache.
- `.vfpc scope` reports selected scope, cache/request status and the latest error.
  Both commands are available in Release builds.
- Clear cache and identity on disconnect, cancel the worker, and reject late
  results using a connection generation. Coalesce reload requests while a load
  is running, retaining one subsequent requested refresh.
- Copy local callsign/facility/controller-permission values inside host callbacks.
  Never retain SDK controller handles. Only plain lookup results cross the worker
  boundary through a mutex-protected pending slot.
- Consume UKCP results and resolve identity before publishing completed airport
  loads. Reuse the existing selected-airport pruning, airport generation,
  cancellation, immutable snapshots and tracked-flight revalidation pipeline.
- Emit scope explanations when they change, rather than on every timer/tag.
  Do not modify EuroScope's Runway Activity selections.

## Rationale and alternatives

Callsign-prefix inference alone cannot represent ESSEX_APP or area sectors.
Runway Activity alone cannot exclude airports outside configured area coverage.
Manually duplicating all coverage lists would add maintenance and divergence.
The supplied UKCP data supports exact position-to-airport filtering; OBS needs a
separate user-selected review scope because its callsigns are absent from that
dataset. Advisory-only UKCP and unrestricted fallback are superseded decisions.

## Consequences and limits

Operational validation depends on usable UKCP data. Initial failure pauses it;
a failed refresh can use the last valid session lookup, so external changes are
not known until a successful refresh. There is no timed expiry within a session.
Selected out-of-coverage airports do not initiate constraint loads, and their
flights display OFF if exposed by EuroScope. Existing in-scope data-loading and
runway-pending states remain PDG.

`top_down` is configured coverage, not proof of live responsibility. This design
does not subtract airports staffed by other controllers or discover delegation.
Exact matching intentionally leaves unsupported aliases paused. FSS and DEP
suffix policies are not inferred; they currently pause as unsupported positions.

## Implementation evidence and verification boundary

Working-source implementation is in `src/analyzeFP.cpp` and `src/analyzeFP.hpp`:
`UpdateControllerIdentity_`, `LoadControllerScopes_`,
`ServiceControllerScopeLookup_`, `ControllerScopeDescription_`,
`RefreshDepartureAirports_`, `OnTimer`, `OnCompileCommand` and teardown.
The user guide and development guidance are updated to describe this decision.

Source changes and static review were followed by separately authorised Debug and
Release Win32 MSBuild builds on 2 November 2026. Both passed with zero warnings
and errors after correcting a console-message overload ambiguity. Outputs were
redirected to the Codex chat output directory; the installed plugin was not replaced.
Subsequently authorised user-operated Sweatbox checks on 2–3 November 2026
confirmed the normal scope cases and successful reloads. An isolated diagnostic
source copy and DLL then confirmed failed-refresh cache retention, no-cache pause,
recovery without reconnect, and OBS operation without a lookup. No fault-injection
hooks were added to production source. The owner restored the normal Release DLL;
its startup log records configuration=Release. See the
[verification record](../../reviews/Controller_Scope_Sweatbox_Results.md) for the
case-by-case evidence and external log locations.

In the observed Sweatbox sessions PR_OBS had facility 0 and server_controller=true.
This does not establish values for other connection modes. No SDK thread affinity,
callback serialisation or stress behaviour is claimed. The coordinator retains
the existing host-callback ownership assumption; its worker handoff is independently
protected. Real transport failures, malformed responses and pending-lookup reconnect
races remain untested. The OFF/VFR reporting discrepancy was subsequently corrected on 3 November 2026:
explicit OFF mnemonics and origin/scope explanations are preserved. Debug and
Release Win32 builds passed with zero warnings/errors. Focused user-operated
Sweatbox checks passed on 3 November 2026 for OFF summary/FULL/logging, genuine
VFR reporting, IFR runway pending and validation resumption. Validation rules
and runway gating did not change. The session is disconnected.
No commits or release deployment were performed by this verification task.

## Outstanding questions

- Identity values outside the specifically observed Sweatbox sessions.
- Whether any actual position aliases require explicitly supported matching.
- Whether future requirements need persistent cache expiry or live staffing rules.
- Host callback concurrency and unload exclusion, inherited from the existing
  coordinator and not established by the SDK declarations.
